# Nexus Backend

API сервиса знакомств Nexus. Подбор людей по смыслу личных рассказов, взаимное раскрытие фотографий и общение после встречных симпатий.

Java 21 · Spring Boot 3.5 · Spring Security · JPA · PostgreSQL / H2 · ONNX Runtime.

## Разработка

Рабочий прототип находится в `main`; история реализации — в [PR #12](https://github.com/SMART-DATING/nexus-backend/pull/12). Новые изменения оформляются отдельными ветками и Pull Request в `main`.

```sh
git clone --branch main https://github.com/SMART-DATING/nexus-backend.git
cd nexus-backend
```

Для локального запуска нужны JDK 21 и доступ к сети при первой загрузке зависимостей и модели. Maven Wrapper включён в репозиторий.

Windows PowerShell:

```powershell
pwsh -File scripts/download-model.ps1
.\mvnw.cmd clean package
java -Xmx512m -jar target/nexus-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

Linux / macOS:

```sh
sh scripts/download-model.sh
./mvnw clean package
java -Xmx512m -jar target/nexus-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

API: `http://127.0.0.1:8080/api/v1`; готовность: `GET /health`. Файловая H2 автоматически создаётся в `data/`, отдельный процесс БД не нужен. Один файл обслуживает одна копия приложения. Консоль H2 отключена.

Интерфейс запускается отдельно из соседнего [nexus-frontend](https://github.com/SMART-DATING/nexus-frontend). Backend без встроенной сборки frontend не обслуживает главную страницу приложения.

## Docker

```sh
docker compose up --build --wait
```

Запускает PostgreSQL 16 и API на 8080. Модель скачивается и проверяется при сборке образа. Для H2 в контейнере: `docker compose -f compose.h2.yaml up --build --wait`. Полный стек с nginx запускается из репозитория frontend.

`docker compose down` сохраняет данные в volume. Не удаляйте volume для обычного перезапуска.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | `local` (H2, по умолчанию) или `postgres` |
| `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD` | Подключение к БД; Compose задаёт внутренний адрес PostgreSQL |
| `NEXUS_MODEL_DIR` | Каталог `model.onnx` и `vocab.txt`; по умолчанию `./models/rubert-tiny2` |
| `NEXUS_DEMO` | Вымышленные аккаунты для разработки; по умолчанию `false` |
| `PORT`, `BIND_ADDRESS` | Порт и интерфейс HTTP; локально 8080 / 127.0.0.1 |

При `NEXUS_DEMO=true` создаются 14 анкет с иллюстрациями и рассказами. Аккаунты `demo@nexus.local`, `demo1@nexus.local` … `demo13@nexus.local`, пароль `NexusDemo2026!`. Существующие заполненные профили не перезаписываются. Это тестовые данные, автоматических ответов в чатах нет.

## Поведение API

- Регистрация создаёт сессию; пароли BCrypt, отзываемые Bearer-токены действуют 24 часа.
- Публичные свойства профиля отделены от личных рассказов. Названия и тексты рассказов получает только автор; векторы не выдаются через API.
- До 12 рассказов по 20–6000 символов. Локальная RuBERT-tiny2 строит 312-мерные векторы; подбор использует косинусное сходство. Публичные темы помогают начать разговор, не заменяют NLP.
- До шести JPEG/PNG. Чужие фотографии раскрываются в пределах количества собственных; доступ повторно проверяется при выдаче изображения.
- Выдаётся самый высокий оставшийся уровень смыслового сходства с шагом 10 процентных пунктов (90–100%, 80–89%, …, 0–9%). Внутри уровня — score по убыванию, затем userId. После всех непросмотренных уровней повторяются собственные Skip; Like не сбрасываются. Галереи и временные ссылки создаются только для выданной страницы.
- Встречные Like создают один match. Чат и уведомления доступны только участникам.
- Match возвращает число непрочитанных входящих сообщений. `PATCH /matches/{id}/read` подтверждает чтение до положительного `throughId`; новые сообщения выше этой границы остаются непрочитанными. Получение истории само по себе не меняет счётчик.

Контракты запросов: [API](https://github.com/SMART-DATING/nexus-docs/blob/main/architecture/api-contracts.md). Модель, лицензия и контрольные суммы: [MODEL.md](MODEL.md).

## Проверки

```sh
./mvnw test
```

На Windows: `.\mvnw.cmd test`. PostgreSQL-сценарии включаются через `TEST_POSTGRES_URL`, `TEST_POSTGRES_USER`, `TEST_POSTGRES_PASSWORD`. CI frontend также собирает PostgreSQL / API / nginx и проверяет реальные HTTP-запросы.

Проверяются права доступа, сессии, приватность, конкурентные Like, круг Skip, галерея, перенос старых данных и эмбеддинги с фиксированными ONNX-весами.

## Эксплуатационные ограничения

Схема обновляется через Hibernate `ddl-auto=update`; версионированные миграции ещё не внедрены. Изображения хранятся в БД, media-ticket — в памяти одного процесса. Подготовка публичного запуска требует HTTPS, модерации, ограничений запросов, восстановления доступа, удаления аккаунта и резервного копирования. Подробности: [архитектура](https://github.com/SMART-DATING/nexus-docs/blob/main/architecture/system-architecture.md).


## Интерфейс и данные

Без сессии `/` открывает информацию о Nexus; `/#login` и `/#register` открывают отдельные формы. Меню приложения открывает знакомства, чаты, профиль и закрытые рассказы «Для подбора». Аватар открывает действия аккаунта. Фото можно раскрыть для просмотра с миниатюрами и жестами; серверная квота сохраняется.

В «Мои данные» доступны скрытие анкеты от новых участников и собственная выгрузка JSON. Пауза сохраняет существующие чаты и не удаляет аккаунт. Выгрузка не содержит токенов, хешей паролей и полученных сообщений.

Сборка предназначена для локальных проверок на вымышленных данных. Готовность публичного запуска не заявляется. [Потоки данных, ограничения и задачи выпуска](https://github.com/SMART-DATING/nexus-docs/blob/main/privacy/data-handling.md).
