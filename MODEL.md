# Локальная текстовая модель

Nexus использует готовую RuBERT-tiny2 для векторного представления личных историй. Обучение на участниках и внешнее inference API не используются. Этот файл фиксирует артефакты и алгоритм; правила очереди описаны в [документации подбора](https://github.com/SMART-DATING/nexus-docs/blob/main/architecture/MODEL.md).

## Установка

Из корня backend: `pwsh -File scripts/download-model.ps1` на Windows либо `sh scripts/download-model.sh` на Linux. Для shell-скрипта нужны `curl` и `sha256sum`; Windows-команда использует PowerShell 7. Скрипт скачивает только веса и словарь из фиксированной ревизии, проверяет SHA-256 и не исполняет код модели. Файлы находятся в `models/rubert-tiny2` и исключены из Git. Каталог переопределяется NEXUS_MODEL_DIR. Docker загружает артефакты во время сборки.

Если отсутствует хотя бы один из файлов model.onnx или vocab.txt, модель не инициализируется: остальные API могут работать, но сохранение истории возвращает 503. Health не проверяет готовность модели. При повреждённом установленном артефакте инициализация может завершиться ошибкой; повторите проверяемую загрузку.

## Алгоритм

1. Cased BERT WordPiece: NFC, очистка control/format, разделение пробелов, пунктуации и китайских символов; регистр сохраняется.
2. Последовательные блоки до 254 содержательных токенов плюс CLS/SEP. Хвост длинного текста не отбрасывается.
3. CLS-вектор каждого блока нормализуется по L2.
4. Векторы блоков суммируются с весом числа содержательных токенов, затем нормализуются.
5. ContextService сохраняет вектор и modelVersion вместе с рассказом. Вектор участника — нормализованная сумма векторов его историй, с равным весом каждой истории.
6. Сходство — скалярное произведение нормализованных векторов, ограниченное [-1,1]. UI показывает round(max(0, score) × 100).

Город, публичные теги, фотографии и реакции не входят в вектор. Город задаёт отдельный приоритет группы при выдаче; после него score ↓ и userId ↑. При иной modelVersion сохранённая история перекодируется. Неизменённые векторы читаются из БД без повторного inference на каждый свайп.

## Ресурсы и проверка

Одна OrtSession использует 2 intra-op и 1 inter-op поток, фоновый spinning отключён. `encode` синхронизирован: параллельные сохранения сериализуются. Native-память модели не ограничивается одним JVM heap.

`SemanticEncoderTest` проверяет эталонные ID токенов, размер/норму, несколько русских парафраз и влияние второго блока. Команды — в [TESTING](https://github.com/SMART-DATING/nexus-docs/blob/main/TESTING.md). Это ограниченные инженерные проверки, не доказательство качества знакомств на реальной аудитории.

Сходство текстов не является вероятностью отношений, проверкой достоверности или диагнозом. Анализ внешности, collaborative filtering и дообучение в текущей версии отсутствуют.
